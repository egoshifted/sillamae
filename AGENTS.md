# Agent instructions

Rules for AI coding agents (and people) working in this repository. The code and README are the source of truth; keep this file short and current.

## Code style

- No narrating comments. Never describe what the code does ("Outline around one building", "Load tiles"). Comment only a non-obvious reason: a constraint, a pitfall, a unit, why the obvious alternative is wrong.
- Match the surrounding code: naming, density, idiom. Small focused functions, no speculative abstractions.
- No AI attribution or co-author lines in commits.

## Layering

- `src/engine/` knows nothing about Sillamäe or any particular building. Town data and refined buildings enter only through `CityDefinition` and `BuildingOverride` (`src/engine/types.ts`).
- `src/city/sillamae/` holds town settings and refined building models. `kesk1/model.ts` is hand-built for Kesk 1 (hard-coded edges, openings, site works), not a reusable archetype.
- `src/studio/` is local study UI, assembly utilities and verification tools; read `src/studio/README.md` for refinement work. Production models may import pure assembly utilities; engine code must not import studio UI/tools. Evidence and reports stay outside the checkout.
- `src/app/` is the React UI. The engine is created once outside React's render cycle (`town.ts` is an external store); components only call its API. Do not create the engine inside a component or effect: HMR and re-renders would start extra engines.
- Roads are generated by the data build; follow [pipeline/ROADS.md](pipeline/ROADS.md) to extend them and never draw streets in building models.
- `pipeline/` is the offline data build in TypeScript run by Node 24 directly (type stripping), hence `.ts` import extensions and `erasableSyntaxOnly`. It runs the same model code as the viewer so ground patches match.

## Data

- Inputs are committed in `data/source/`; `public/data/` is generated by `npm run data` and never committed.
- Survey vertices are 7 floats: x, z, h, r, g, b, pick (building index, 0 = ground).
- Survey ground is 2–5 stacked layers (5–35 cm apart) over a sea-level plane of ~281 huge water triangles. Never move ground layers independently or use the sea plane as the base surface; see `src/engine/survey/drape.ts`. Ground overlays need a depth lift appropriate to their actual survey layers (stairs use 1 m). Do not copy that lift blindly to aprons: excess bias can draw buried surfaces through foundations.
- The tile loader inflates only when the body still starts with the gzip magic bytes, because some servers (the Vite dev server) already decode `.gz`.
- Overpass: use bbox queries; area-by-name queries hang.

## Checks

- `npm run check` (type check) must pass; `npm run build` must succeed.
- Refactors that should not change rendering must keep fixed views pixel-identical to the last accepted build (renders are deterministic). Survey bucket order is preserved because equal-depth survey meshes draw in creation order.
- For headless checks against the dev server pass `--host 127.0.0.1`; Vite listens on IPv6 `localhost` by default.

## Documentation

- Keep README.md for global and structural documentation. Do not add individual building updates, progress notes or review status; keep these in the local review records outside the repository.

## Scope

- People/agents simulation is deferred by the project owner. Do not start it unprompted.
